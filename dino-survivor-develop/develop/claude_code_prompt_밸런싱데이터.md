# DinoSurvivor 밸런싱 데이터 구현 요청

## 0. 작업 전 필수 확인사항 (중요)

**코드를 작성하기 전에 먼저 다음을 확인하고 계획을 세워줘:**

1. 기존 스폰 시스템(적 스포너, 웨이브/타이머 관리) 코드 구조를 확인해줘 — 어떤 씬/스크립트가 스폰 타이밍을 담당하고 있는지, 데이터가 하드코딩되어 있는지 아니면 Resource/JSON 등으로 분리되어 있는지.
2. 기존 스킬 시스템(레벨업, 스킬 데이터 정의) 구조를 확인해줘 — 스킬 13종이 어떤 형태(Resource, class, dictionary 등)로 정의되어 있는지, 레벨업 후보 제시 로직이 어디 있는지.
3. 기존 아이템/드랍 시스템이 있다면 구조를 확인해줘 (엘리트/보스 처치 드랍, 필드 드랍 등).

**확인이 끝나면, 아래 데이터를 이 기존 구조에 "맞춰서" 넣을 구체적인 계획(어떤 파일을 새로 만들지, 어떤 기존 파일을 확장할지)을 먼저 텍스트로 제시해줘. 내가 승인하면 그때 실제 구현을 시작해줘.**

**절대 하지 말아야 할 것:**
- 기존 오토로드/매니저 스크립트의 책임 범위를 임의로 바꾸는 것
- 기존 네이밍 컨벤션과 다른 스타일을 새로 도입하는 것
- 기존에 Resource 기반으로 되어 있는 걸 하드코딩으로 바꾸거나 그 반대로 바꾸는 것 (기존 패턴을 따를 것)
- 기존 스크립트를 통째로 재작성하는 것 (확장/추가 위주로)

- 몬스터는 현재 구현된 몬스터와 동일한 방식으로 데이터를 만들어. 현재 구현된 두 가지 몬스터는 각각 lv1, 2로 취급하고 lv당 스탯이 증가하도록 설계. 단, 추후 각각의 특징을 살려서 스프라이트를 추가하고 밸런싱할 예정.

## 2. 강화트리거 & 스킬 성장 밸런스 시트

'강화 트리거' 아이템 추가: 드랍 시 '강화' 혹은 '합체' 라는 두 가지 선택지 제시, '강화'는 랜덤으로 보유 스킬을 1~5회 레벨업 시킴. (먼저 강화 시행횟수를 랜덤으로 결정하고, 각 시행마다 어떤 스킬을 레벨업할지 랜덤으로 결정하는 방식.) '합체'는 합체가 가능한 스킬이 있을 경우 활성화되며 UI에 합체 가능 스킬이 표시되고, 선택하면 기존의 두 스킬이 사라지고 합체 스킬이 슬롯에 들어감. '합체 레시피'는 추후 구현 예정


### 스킬 구조
- 액티브 6개 / 패시브 6개 = 총 12개
- 패시브 만렙: 레벨 5
- 액티브 만렙: 레벨 5 + 진화(레벨 6에서 진화 발동) > 레벨업 시 등장하는 선택지에 'lv5->lv6' 대신 '진화'로 등장. 선택 시 진화 선택지를 보여주는 UI(레벨업 UI와 동일한 구조)가 등장하고 선택할 수 있도록 함.
- 액티브 진화는 스킬당 1~3가지 분기가 있고, 일부는 유저가 직접 선택, 일부는 특정 패시브 레벨 조건으로 해금
- 합체(스킬 융합)는 **진화를 마친 액티브끼리만** 가능하며, 고정 레시피(어떤 액티브+액티브가 합쳐지는지 사전 정의)를 따름
- 합체 시 소모된 액티브 슬롯 중 하나는 "합체완료(레벨업 불가, 고정)" 상태가 되고, 다른 하나는 슬롯이 리셋되어 새 액티브를 다시 획득할 수 있음

### 성장 소스 (15분 세션 기준)
| 소스 | 빈도/방식 | 효과 |
|---|---|---|
| 일반 레벨업(XP) | 평균 30회, 매번 3개 후보 중 택1 | 선택한 스킬 1레벨 상승 |
| 강화트리거 - 확정 드랍 | 엘리트 5회 + 중간보스 2회 + 보스 1회 = 8회 | 유저가 "강화" 또는 "합체"(만렙+진화 액티브 2개가 레시피에 맞으면) 중 선택 |
| 강화트리거 - 레어몬스터 드랍 | 중간 확률 | (드랍률 미확정 파라미터로 유지, 현재 밸런스 기준값 0%로 설계됨 — 추후 조정 여지 있음) |
| 강화트리거 - 맵 필드 드랍 | 세션당 4개 배치, 약 70% 발견율 가정 | 확정 드랍과 동일 |

### 밸런싱 목표치 (시뮬레이션 기반 확정값)
- 15분 세션 평균 합체(스킬 융합) 발생 횟수: **약 1.6회**
- 분포: 0회 약 3%, 1회 약 40%, 2회 약 50%, 3회 이상 약 5%
- 즉 "합체를 한 번도 못 하는 경우는 드물고, 기본적으로 1~2번 정도 경험하는 게 표준, 3번 이상은 운이 좋은 경우"가 목표 체감

## 3. 요청 작업

1. 위 확인사항(0번)에 따라 기존 구조 파악 → 계획 제시 → 승인 후 구현 순서로 진행
2. 몬스터 타임테이블을 기존 스폰 시스템 패턴에 맞는 데이터 형태로 추가 (하드코딩 여부는 기존 관례를 따름)
3. 강화트리거 시스템(확정 드랍/맵드랍/레어몬스터 드랍, 강화-합체 선택 로직, 합체 레시피 매칭)을 기존 스킬 시스템 구조에 맞게 추가
4. 밸런싱 목표치(평균 합체 1.6회)를 검증할 수 있는 간단한 디버그/테스트 수단이 있으면 좋겠음 (예: 헤드리스 모드에서 N회 시뮬레이션 돌려서 평균 합체 횟수 로그 출력 등) — 기존에 Godot 헤드리스 테스트 워크플로우가 있다면 그걸 활용
