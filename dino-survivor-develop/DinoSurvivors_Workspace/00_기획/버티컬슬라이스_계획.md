### 진화 완료 스킬의 재등장 = 의도된 사양 (확정)
`skill_controller.evolve_skill()`이 원본을 보유 목록에서 지우므로, 진화를 마친 스킬의 원본은 레벨업 카드에 다시 등장해 처음부터 다시 키울 수 있음. **버그가 아니라 사양으로 확정.**
단 액티브 슬롯이 꽉 찬 상태에서는 후보에서 제외되므로(VS-1), 실제로 재등장하려면 빈 슬롯이 있어야 함.

### VS 이후로 미뤄도 되는 것
- 스탠스 전환 (enum만 존재)
- 유전 시스템 (전무)
- 캐릭터 숙련도 (리소스 타입만, autoload·데이터·UI 없음)
- 패시브 스킬 (스키마만, "태그.효과필드" 계산기 없음 / 패시브 `.tres` 0개)
- 도감 콘텐츠
- 잔여 스킬 4종 (정전기 / 정찰비행 / 바다의 공포 / 가시 궤적)

## 4. 단계 계획

### VS-1. 선택의 구조 — ✅ 구현 완료
**목표**: 15분 런에서 최소 스킬 4개(합체 재료 2개 포함)를 안정적으로 Lv.5까지.

구현 내용:
- 액티브 슬롯 6개 제한 (`RunState.ACTIVE_SLOT_COUNT`). 패시브 스킬은 슬롯을 차지하지 않음
- 슬롯이 꽉 차면 미보유 액티브를 카드 후보에서 제외 → 보유 스킬 레벨업만 제시
- 가중치(피티): 보유 스킬 3배 (`level_up_ui.gd`의 `OWNED_SKILL_WEIGHT`)
- XP 곡선 재설계: `20 + (level-1) * 12` (기존 `10 + (level-1)*5`)
- 개발자 메뉴에 곡선 튜닝용 계측 표시 추가 (경과/레벨/슬롯/만렙 수/누적 XP/분당 XP/**15분 예상 레벨**)

#### 픽 예산 시뮬레이션 결과 (20,000회 시행)
슬롯 6개 × 5레벨 = **30회가 픽 예산의 구조적 상한**. 30회를 넘기면 모든 슬롯이 진화를 마쳐 제시할 카드가 사라짐.

| 레벨업 | 집중형 플레이 | 무작위 플레이 | 낭비 픽 |
|---|---|---|---|
| 24회 | 4.00개 (99.5%) | 2.74개 (12.6%) | 0 |
| 26회 | 5.00개 (100%) | 3.54개 (54.9%) | 0 |
| **28회** | **5.00개 (100%)** | **4.51개 (100%)** | **0** |
| 30회 | 6.00개 (100%) | 6.00개 (100%) | 0 |
| 32회 | 6.00개 (100%) | 6.00개 (100%) | 2 |

→ **28회로 확정** (`RunState.TARGET_LEVELUPS`). 어떻게 플레이해도 4개 이상은 100% 확보되지만 6개 전부를 진화시키지는 못해 선택의 의미가 남는 지점. 당초 논의했던 32회는 상한 30을 넘겨 빌드가 전부 고정되고 마지막 2회가 죽은 픽이 되므로 폐기.

#### 함께 수정한 것
슬롯이 전부 진화로 채워지면 카드 후보가 0개가 되는데, 기존 `_open()`은 카드 0장 상태로 팝업을 띄우고 일시정지해 **선택이 불가능한 소프트락**이 발생함 → 후보가 없으면 팝업을 띄우지 않도록 수정. (합체는 재료 2개를 1개로 합쳐 슬롯을 돌려주므로, VS-2 이후로는 이 상태에 잘 도달하지 않게 됨)

#### 남은 검증
XP 곡선 계수는 "15분에 약 5,100 XP 수급" 가정으로 역산한 값이며 **실측 전**. 개발자 메뉴의 "15분 예상 Lv." 표시가 목표(Lv.29)에 붙도록 실플레이로 `XP_BASE`/`XP_GROWTH` 조정 필요. 타임스케일 3x를 쓰면 한 판 5분에 측정 가능.

### VS-2. 합체 (1.5주) — 게임의 킥 ⬅ 다음 작업
**레시피 확정: `알폭탄 진화A(왕특란) + 침뱉기 진화A(맹독지대) → 백린란`**
기획서 4.3의 `새끼낳기 + 음파`는 두 스킬 모두 미구현이라 폐기. 백린란은 `스킬설계.md` 3장에 이미 컨셉이 작성되어 있고, 두 재료 모두 진화까지 구현 완료라 즉시 착수 가능. 즉발 폭발 + 지속 장판의 이중 구조라 태그도 겹치지 않음.

- `data/fusion_recipes/`에 백린란 레시피 `.tres` 작성 (`FusionRecipe` 스키마는 이미 존재)
- 정예 몹 드랍 트리거 아이템 (LootTable 인프라는 이미 있음 — 엔트리 추가로 해결)
- 재료 스킬 진화 완료 감지 → 트리거 보유 시 합체 발동 판정
- 합체 결과 스킬(백린란) 구현 + 슬롯 대체 로직 + 발동 연출
- 재료 2개가 1개로 합쳐지며 **액티브 슬롯 1칸이 반환**됨 — VS-1의 "슬롯 포화" 상태를 푸는 유일한 밸브

### VS-3. 런의 완결 (1주)
- **클리어 조건: 보스 처치형으로 확정** (시간 생존형 폐기). 현재 보스는 180초에 1회 스폰 후 방치 상태 → 처치 시 런 종료 + 클리어 결과 화면으로 연결
- 탈피(긴급탈출): 전용 버튼 / 일시정지 / 반납 스킬 선택 UI / 화면 클리어 / 쿨타임
- 결과 화면 (생존시간 · 처치수 · 획득 골드 · 최종 빌드) — 클리어/게임오버 공용

### VS-4. 캐릭터 축 (1주)
- `skill_controller.gd`의 시작 스킬 하드코딩 제거 → `SpeciesData.starting_skill` 연동
- 캐릭터 3종 확정 권장: **티라노(물기) / 미크로랍토르(깃털다트) / 오비랍토르(알폭탄)** — 셋 다 스킬 구현 완료
- 더미 종족 3종 정리, 종족 패시브 실수치 부여
- 화석 복원에 실제 해금 비용(골드) 연결 (현재는 조건 없이 즉시 해금)

### VS-5. 체감 폴리시 (1.5주)
- 사운드 최소 세트 (타격 / 획득 / 레벨업 / 진화 / 사망)
- 히트스톱 · 스크린셰이크 · 데미지 넘버 · 처치 이펙트
- 보스 등장 연출, 웨이브 난이도 커브 튜닝
- placeholder 교체 우선순위: 적 > 스킬 이펙트 > 타일

### VS-6. 플레이테스트 & 문서 동기화 (지속)
- 외부 테스터 3~5명 대상 테스트
- 기획서 v0.5 현행화 — 로비 / 화석복원 / 도감 / 청크맵이 문서에 아예 없고, 마일스톤 표가 실제와 4단계가량 어긋나 있음

**합계 약 6~7주** (2인 기준, 버퍼 포함) — VS-1 완료분 제외 시 잔여 약 5~6주

## 5. 확정된 결정 (2026-08-14)

1. **합체 레시피는 백린란으로 교체** — `알폭탄 진화A(왕특란) + 침뱉기 진화A(맹독지대) → 백린란`. 기획서 4.3의 `새끼낳기 + 음파`는 두 스킬 모두 미구현이라 폐기.
2. **런 클리어 조건은 보스 처치형** — 시간 생존형 폐기.
3. **잔여 스킬 4종은 동결** — 정전기 / 정찰비행 / 바다의 공포 / 가시 궤적은 슬라이스 이후.
4. **진화 완료 스킬의 재등장은 사양** — 버그로 취급하지 않음 (2장 참고).
5. **레벨 목표는 15분 / 레벨업 28회 / 최소 4개 Lv.5** — VS-1 시뮬레이션 근거.
6. **경험치 자석(`pickup_range`)은 슬라이스 범위 밖** — 젬은 직접 밟아 회수. 이로 인해 원거리 빌드의 XP 수급이 근접 빌드보다 낮은 것은 감수하며, XP 곡선은 실측 평균에 맞춘다.

## 6. 튜닝 포인트 (코드 수정 없이 숫자만 만지는 지점)

서브 개발자가 직접 조정 가능한 값들입니다. 전부 상수 한 줄이라 다른 로직에 영향을 주지 않습니다.

| 값 | 위치 | 현재 | 의미 |
|---|---|---|---|
| `XP_BASE` | `autoload/run_state.gd` | 20 | Lv1→2에 필요한 경험치 |
| `XP_GROWTH` | `autoload/run_state.gd` | 12 | 레벨당 필요 경험치 증가폭. **올리면 레벨이 느려짐** |
| `TARGET_LEVELUPS` | `autoload/run_state.gd` | 28 | 15분 런의 목표 레벨업 횟수 (개발자 메뉴 표시 기준) |
| `ACTIVE_SLOT_COUNT` | `autoload/run_state.gd` | 6 | 액티브 스킬 슬롯 수 |
| `OWNED_SKILL_WEIGHT` | `scripts/ui/level_up_ui.gd` | 3.0 | 보유 스킬이 카드에 뜰 가중치 배수. **올리면 한 스킬에 집중하기 쉬워짐** |
| `CARD_COUNT` | `scripts/ui/level_up_ui.gd` | 3 | 레벨업 시 제시하는 카드 장수 |
| 몹 스폰 간격/마리수 | `data/enemies/*.tres` | — | `spawn_interval` / `spawn_count_per_tick` |
| 드랍 확률/개수 | `data/loot_tables/*.tres` | — | 항목별 `drop_chance` / `min_count` / `max_count` |
| 젬 경험치량 | `scenes/entities/pickups/XPGem*.tscn` | 5 / 10 / 20 | 소 / 중 / 대 |

### 튜닝 방법
개발자 메뉴(`~` 키)를 열면 최상단에 다음이 표시됩니다.
```
03:45  Lv.9  슬롯 4/6  만렙 1개  누적XP 620
분당 165 XP → 15분 예상 Lv.24 (목표 29)
```
**"15분 예상 Lv."가 목표에 붙도록 `XP_GROWTH`를 조정**하면 됩니다 (예상이 목표보다 낮으면 `XP_GROWTH`를 내리고, 높으면 올림). 같은 메뉴의 타임스케일 3x를 쓰면 15분 런을 5분에 측정할 수 있습니다.

### 2026-08-14 — 계획 수립 + VS-1 구현
**계획 수립**: 코드 전수 확인으로 현재 상태를 재파악하고, 기획서 v0.4와의 괴리(문서상 G3 / 실제 G7+메타 레이어)를 확인. 슬라이스를 막는 공백 6가지를 정리하고 VS-1~VS-6 단계를 정의.

**VS-1 구현** (수정 파일 3개):
- `autoload/run_state.gd`
  - `ACTIVE_SLOT_COUNT = 6` 및 `active_skill_count()` / `has_free_active_slot()` 추가. 패시브 스킬은 슬롯을 차지하지 않음
  - XP 곡선을 `10 + (Lv-1)*5` → `20 + (Lv-1)*12`로 교체. `TARGET_LEVELUPS = 28` 신설
  - 튜닝 계측용 `total_experience` 누적 및 `total_xp_for_level()` 헬퍼 추가
- `scripts/ui/level_up_ui.gd`
  - `pool.shuffle()` 순수 랜덤을 **가중 추출**로 교체 (`OWNED_SKILL_WEIGHT = 3.0`)
  - 슬롯이 꽉 차면 미보유 액티브를 후보에서 제외하는 `_candidate_skills()` 추가
  - 후보가 0개일 때 팝업을 띄우지 않도록 `_open()`에 가드 추가 (소프트락 수정)
- `scripts/debug/dev_menu.gd`
  - 곡선 튜닝용 계측 표시 추가 (경과 / 레벨 / 슬롯 / 만렙 수 / 누적 XP / 분당 XP / 15분 예상 레벨)

**검증**:
- Godot 4.7 헤드리스로 Main 씬 부팅 및 런타임 동작 확인 (상수 접근, 카드 3장 추출 정상)
- 픽 예산 시뮬레이션 20,000회 시행 → 4장 VS-1의 표

**발견 사항 2건**:
1. **픽 예산의 구조적 상한은 30회** (슬롯 6 × 레벨 5). 당초 논의한 32회는 이를 넘겨 모든 슬롯이 진화로 고정되고 2회가 죽은 픽이 됨 → 28회로 하향 확정.
2. **슬롯 포화 시 소프트락**. 6슬롯이 전부 진화를 마치면 카드 후보가 0개가 되는데, 기존 `_open()`은 카드 0장으로 팝업을 띄우고 일시정지해 선택이 불가능했음 → 가드 추가로 해결.

**미완료**: XP 곡선 계수는 "15분에 약 5,100 XP 수급"이라는 추정치로 역산한 값이며 **실측 전**. 6장의 튜닝 방법으로 실플레이 측정 후 확정 필요.
